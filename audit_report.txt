## Done by Pablo
- Scope: Data Leakage, Train and Test Split
  Lectures followed: Preventing Data Leakage, Data Splitting
1. Data Leakage Columns that we should drop from the df.csv dataset:
   - discharge_location: contains entries with 'DIED' -> Direct Target Leakage
   - expire_flag: same as our target -> Direct Target Leakage
   - dod: having a dod value means patient died -> Direct Target Leakage
   - deathtime, dod_hosp, dod_ssn  : reveals death -> Direct Target Leakage
   - dischtime, outtime, los (length of stay), last_careunit, last_wardid, edouttime: 
      we want to predict if a person will die before admission. these variables are only know after admission or after the outcome -> Temporal Leakage
   - has_chartevents_data: not leakage per se but can be a predictive proxy, patients with 
      has_chartevents_data = 1  → likely severe → higher mortality risk
      has_chartevents_data = 0  → likely mild → lower risk
   - dob: not leakage per se but should be changed to 'age', age = admittime − dob
   - admittime: same as above
   - we should also drop all the duplicated columns: row_id_x, row_id_y, row_id, subject_id, hadm_id, icustay_id
2. Train / Test Split: there are 2 issues in the audit regarding the data Split
   1. The split is after the preprocessing when it should be before 
      - moved the split up so it's done before preprocessing
   2. Same patient can appear in both Test and Train split (multiple admissions) because data is split randomly ->  Failure to Consider Dependent Samples Data Leakage
      - in the lecture she deals with this by using GroupKFold (DataLeakage page 8)
      - it should be stratified -> used StratifiedGroupKFold
      - adapted the preprocessing to this
      - adapted the GridSearch to this

## Done by Ons
- I added outlier detection for the age column using the IQR method, following the Outliers lecture, which compares thresholds of 0.5, 1.5, 2.5, and 3.0 and settles on 2.5 as a reasonable middle ground between flagging too many points and missing real outliers. I limited the check to age because the pipeline's other numeric columns are identifiers or codes (subject_id, first_wardid), not real measurements and length of stay already has its own dedicated 99th-percentile cap earlier in the pipeline. To avoid leakage, the lower/upper bounds are computed from the training split only and reused unchanged on the test split so it's consistent with how every other preprocessing step in this pipeline already treats train vs. test. Outlier values are set to missing rather than dropped outright, so they flow into the existing median-imputation step right after instead of needing separate handling.
- I dropped intime because it's basically a timestamp, not a real category because almost every row has a different value, so grouping it into "Other" wouldn't really mean anything. For the other categorical columns, I used the cardinality cutoff of 15 from the lecture: if a column had more than 15 categories in the training data, the rare ones got grouped into "Other". This only affected diagnosis, which had 82 different values in training, so now it's reduced to the top 15 plus "Other" instead of creating a bunch of almost-empty dummy columns.
- I removed subject_id from the final model features: It was slipping through as a raw ID column even though hadm_id/icustay_id were already dropped. An identifier like this has no real predictive meaning and shouldn't be a model input, even though the patient-grouped split already prevents it from causing test-set leakage.
- I added missingno matrix and bar plots right after outlier removal, (like done in lecture Outliers) which shows plots only after outliers have been handled ( not on the raw data). They're generated from the training split, once outlier values have already been turned into NaN but before they get filled in, so the plots actually show what needs imputing at that point.
Plots added to the plot folder are missing_bar and missing_matrix
- I added a histogram (nan_per_row) showing how many missing values each row has, using bins=30 as the lecture does. Most rows (94 out of 109 in the training split) have no missing values at all, 14 rows are missing exactly one value, and only 1 row is missing two so missingness here is minor and concentrated in a couple of columns (religion, marital_status), not spread out across many rows.
- I added a histogram and boxplot for age labeled "(Cleaned)", generated after outlier removal and imputation. Note: the boxplot still shows a few points as circles below the whiskers.. i googled that and it seems to be just matplotlib's own default boxplot rule (1.5×IQR), separate from the 2.5×IQR threshold actually used to clean the data.
Plots added to the plts folder: age_histogram_cleaned.png and age_boxplot_cleaned.png
